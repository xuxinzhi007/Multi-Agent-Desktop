## P0-1 · 网关两处并发缺陷（约 1 小时）

### ① Broker send-on-closed panic

`internal/gateway/broker.go:50-63` `Publish`：锁内拷贝 `subs` → 解锁 → 逐通道 `select { case ch <- ev }`。
`internal/gateway/broker.go:77-88` `Unsubscribe`：锁内 `delete` → 解锁 → `close(ch)`。

后果：Publish 已知某通道存在（快照里），Unsubscribe 随后关闭它，发送瞬间 panic。触发条件是**并发断开 SSE**，桌面端切页签/关窗口就能撞上，且 panic 打在主进程里。

改法（二选一，都可行）：

1. 发送与关闭共用同一把锁：`close` 移到锁内，发送也在锁内做非阻塞 select（通道有 32 缓冲，阻塞概率低）。
2. 每订阅配一个 `done chan struct{}`，`Unsubscribe` 只 `close(done)`，Publish 用 `select { case ch <- ev: case <-done: }`，永不关业务通道。

验收：`go test -race ./internal/gateway/...`，补一条「并发 Publish + Unsubscribe」用例（现有测试未覆盖）。

### ② `main.go` 的 `gw` 读写竞态

- 声明：`main.go:1490` `var gw *gwhost.Host`
- 读：`main.go:1515-1516` `emit` 闭包内 `if gw != nil { gw.OnAgentEvent(...) }`
- 写：`main.go:1687` `gw, gwErr = gwhost.New(...)`，`:1702` `api.gw = gw`

`emit` 从 Manager 启动起就可能被其他 goroutine 调用，而赋值在 1687 —— 未同步读写，`-race` 必报。

改法：`atomic.Pointer[gwhost.Host]`，或把 `gw` 赋值提到 `mgr` 创建、`SetEmitter` 之前。后者更简单：先 New 网关（失败就留 nil），再装 emitter。

验收：`go build ./...` + `go test -race ./internal/agent/...`（跑得慢，可只跑含 emit 的包）。
