# 对标主流 AI 编码工具：速度与协作改造

> 2026-11-26 · 基于 HEAD `151779f` + 当日在改文件 · 与 `direction-cli-first-2026-11-26.md` 配套
> 本文只讲**怎么变快、怎么变能协作**，不讲新功能。每条都标注了改动位置与收益来源。

## 0. 一句话

主流工具的快，不是模型快，是**少往返**：一次多读、一次多改、不重复思考、不等人点。
我们现在是**每个动作都单独走一趟**，所以慢在结构上，不在模型上。

## 1. 五家的共同设计

| 维度 | Claude Code | Cursor | Cline | Codex CLI | Aider | 共性 |
|---|---|---|---|---|---|---|
| 目录 | cwd + `--add-dir` 显式加 | 打开的工作区（可多根） | workspace root | cwd + sandbox 策略 | 仓库根 | **一组显式根，不扫盘** |
| 只读工具 | 一轮可并发多个 read/grep | 并发读 | 串行（较慢） | 并发 | 并发 | **并发是默认** |
| 编辑 | 精确 old_string / patch | apply diff | 精确替换 | patch | edit block + repo map | **patch 化，少一轮确认** |
| 审批 | allowlist + 会话内允许 | 默认自动，可 Undo | auto-approve 列表 | suggest / auto-edit / full-auto 三档 | 默认自动 | **策略化，不是每步问** |
| 上下文 | 压缩一次、复用 | 索引 + 智能截断 | 截断 | 截断 | repo map（token 换准确度） | **压缩不重复做** |
| 子任务 | Task subagent：独立上下文、返回摘要 | 多 tab agent | 无 | 无 | 无 | **轻量子任务** |

五条共性，我们没有一条是完全对齐的。

## 2. 我们与主流的差距（按「每轮往返」计）

| # | 维度 | 主流 | 我们 | 每轮代价 |
|---|---|---|---|---|
| 1 | 只读工具执行 | 并发 | **严格串行**：`loop.go:391` 的 `for _, c := range turn.Calls`，`internal/loop` 与 `internal/tool` 全包无 `errgroup`/`WaitGroup` | 读 5 个文件 = 5 次模型往返的等待 |
| 2 | 编辑 | patch | 已有 `apply_patch`（`builtin.go` RegisterRoots 内） | 已对齐，无需改 |
| 3 | 上下文压缩 | 压一次、复用 | **每轮判断、可能重算**：`loop.go:307` / `:326` → `compact` → `llm/compact.go:96`；预算只有 `sys+8000+400`（`loop.go:476-477`） | 中长会话几乎每轮多一次模型调用 |
| 4 | 前缀缓存 | Anthropic 打 `cache_control`；OpenAI 兼容自动 | **只记账、不标记**：`internal/llm/usage.go` 已统计 `cached_tokens`，但请求体里没有 `cache_control`（grep 仅命中 usage 与测试） | 首 token 变慢、成本不降（Anthropic 系） |
| 5 | 审批 | 策略化 | 默认 `ask` 三档，每步一次点击 | 每写一步 +1 次人工延迟 |
| 6 | 子任务 | 轻（同进程、新上下文、回摘要） | **重**：子会话 + 每子任务 `worktree.Add`（`delegate.go:140`）+ 20 分钟时限 | 每个子任务多几百 ms~数秒的 git 开销 |
| 7 | 目录 | 显式根 + 工具自由探索 | 单根 + `bash` cwd 钉死（`builtin.go:116`） | 跨项目任务必须反问「给我路径」 |

## 3. 速度账：一次「修个 bug」现在花在哪

```
发消息 → 入队(a.queue) → 首 token ──┬─→ 模型想
                                    ├─→ 串行 read A → 等
                                    ├─→ 串行 read B → 等      ← 可并成 1 次
                                    ├─→ 串行 grep  → 等
                                    ├─→ 模型再想（可能触发摘要重算）← 可省
                                    ├─→ apply_patch
                                    ├─→ 等你点「允许」        ← 可省（策略化）
                                    ├─→ verify（上限 180s）
                                    └─→ 汇总
```

可压缩的三段：**串行读**（收益最大）、**摘要重算**、**审批等待**。这三段都不涉及模型质量，纯结构。

---

## 4. 协作账：轻子任务 vs worktree 子会话

现在的 `delegate` 对每个子任务**无条件**开 worktree（`delegate.go:140`）。这对「几个 agent 同时改代码」是对的，
对「顺手查一下另一个项目」是纯开销——查资料不需要隔离文件系统。

主流做法（Claude Code 的 Task）：同进程、新上下文、只回摘要、不隔离仓库。

建议按任务类型分流：

| 子任务类型 | 形态 | 隔离 |
|---|---|---|
| 读 / 搜 / 分析 / 调研 | 轻 subagent：同 process、共享 roots、独立上下文、返回文本 | 不需要 worktree |
| 改代码 / 跑测试 / 长期 | 现状：子会话 + worktree + 分支 | 保留 |

判据可以交给模型（`delegate` 入参加 `mode: "read" | "write"`），也可以由代码按工具面推断。

## 5. 改造清单

### P0（改手感与速度，全部是结构改动，不碰模型）

**P0-1 只读工具并发**（半天，收益最大）
`loop.go:391` 那个 for：把 `Writes()==false` 的工具（`read_file` / `grep` / `glob` / `web`）并发执行，
写类与 `bash` 保持串行；结果按 `Calls` 原序回填，保证消息序列不变。
预期：一次读 5 个文件从 5 次等待变 1 次。

**P0-2 审批策略化**（半天）
默认 `auto`；`ask` 降级为「谨慎模式」；「本会话允许」已有，补「这个工具以后都允许」（按工具名 + 根目录）。
预期：日常点「允许」次数从几十降到个位数。

**P0-3 工作区根 + cwd 可移动**（1 天）
见 `direction-cli-first-2026-11-26.md` P0-1：`bash` 可选 `cwd`、`glob`/`grep` 跨根、提示词列roots。
预期：跨项目任务 0 次反问。

### P1（提速，各自独立）

**P1-1 摘要 Epoch 冻结**：`State` 加 `SummaryAtIter`，只在「又增了 N token」时重算。
**P1-2 前缀缓存标记**：Anthropic 形状的 provider 打 `cache_control`（系统提示 + 最近稳定段）；OpenAI 兼容的靠服务端自动，不用改。
**P1-3 轻子任务**：`delegate` 加 `mode`，读类子任务不开 worktree。
**P1-4 verify 瘦身**：默认只验改动包（`go build ./<pkg>` 或 `go test ./<pkg>`），全量留给收尾。

### P2（先不做）

- repo map / 语义索引（Aider 那条是「token 换准确度」，我们预算只有 ~8k，换了更亏）；
- 自动接受全部编辑（有 audit + shellguard 就不该放弃策略层）；
- 多 tab 并行 agent（先把单会话跑顺）。

## 6. 不抄的三样（写清理由，免得反复讨论）

1. **托管式云端索引**：Cursor 的索引是服务端的，我们本地 grep 零审批已经够；引入索引=引入同步与失效问题。
2. **每轮注入 repo map**：预算 8k，注入 1k 的 map 等于砍掉 12% 的对话空间。
3. **无审批自动改全仓**：我们有多根工作区之后，误改半径会变大，审计必须留着。

## 7. 验收指标（可量化，不靠体感）

| 指标 | 现在 | 目标 |
|---|---|---|
| 读 5 个文件的往返次数 | 5 | 1 |
| 一次「改 + verify」端到端（不含模型思考） | 含 1 次审批等待 + 全量 verify | < 40s，0 次等待 |
| 每天点「允许」次数 | 几十 | ≤ 5 |
| 跨项目任务反问「路径是什么」 | 每次 | 0 |
| 中长会话每轮模型调用数 | 2（正常 + 摘要） | 1 |
