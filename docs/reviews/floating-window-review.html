基线：拖动不是 CSS 属性，是「拦截 mousedown」

mygo 的实际判定

flowchart TB

  C2 -->|否| STOP2[什么都不做]

  style PD fill:#fef2f2,stroke:#dc2626

INTERACTIVE = input,textarea,select,button,a[href],summary,label,[contenteditable],video[controls],audio[controls]

两个必然后果

① 拖动区域内的点击被 preventDefault 吃掉

--app-region: drag 覆盖的区域，只要目标不是 INTERACTIVE 元素， mousedown 就被 preventDefault()。 于是 <div onClick> 的点击永远不触发—— 因为 React 的单击也依赖 mousedown/up 序列，而这里被拦了。

② 拖动区域是「继承」语义，不是包围盒

--app-region 用 getComputedStyle(el) 读， 不是 -webkit-app-region 那种向上走父链的语义。 写了 drag 的容器，它的所有后代都读不到，除非自己再写一次。

已证实 · 主窗口完全无法拖动

主窗口是 Frameless: true（main.go:999）， 但 grep app-region src/ 只有 mini.tsx 两处命中。 主窗口整页没有任何 drag 区域 —— 它没有标题栏，也没有可拖的地方。 这不是「体验不好」，是它只能靠系统快捷键或别的窗口移。

1 · 状态点既是拖动手柄又是点击目标，两者互斥

src/mini.tsx:124 --app-region:drag 放在根节点 · :165-171 状态点的 onClick

Strong in-process

Before · drag 覆盖整条，点击被吃掉

--app-region: drag

根 div（整条 380×52）

状态点 onClick 不触发
「舰队」文字 · 统计文字
按钮
按钮
button → 可点

状态点是 <div onClick>，不是 button， 因此 closest(INTERACTIVE) 为 false → mousedown 被拦 → 点击永远不生效。 拖和点抢同一块区域。

After · 手柄与点击面分离

⇔ drag click
状态点 button · 可点
空白拖动条

· 可交互元素一律用 button（进 INTERACTIVE 白名单）

· --app-region: drag 只给专门的空白手柄区

· 状态点移出 drag 容器，或显式写 no-drag

Problem

drag 区覆盖整条悬浮栏，而状态点用 div + onClick 实现。mygo 的判定只豁免 button/input/a 等标签，div 不在白名单，于是 mousedown 被 preventDefault，点击丢失。

Solution

把「窗口手柄」和「内容」做成两个明确的 module：一个 DragHandle 只负责拖，一个交互面负责点。所有可点元素用 button，drag 只覆盖空白区。

Wins

  • · 点击和拖动不再互斥，各自独立
  • · locality：「能拖哪」集中在一处，不再散落
  • · 主窗口顺带补上拖动手柄（现在完全没有）
  • · 可测：手柄区域是显式元素，可断言其存在

After · 语义分层

hover

显示 tooltip · 就地预览，不改变任何状态

单击

选中该 agent（就地高亮），不隐藏窗口

双击 / 明确按钮

跳转主窗口并隐藏悬浮窗

右键

现在是「直接 stopAgent」，无确认 —— 危险动作绑在右键

Problem

onClick 和 onDoubleClick 绑同一个函数（mini.tsx:166-168），而且这个函数会 Hide() 悬浮窗。右键直接 stopAgent，零确认。

Solution

把「查看 / 选中 / 跳转 / 停止」拆成四个不同意图，各自对应各自的交互。停止类动作必须有确认或撤销。

Wins

  • · 看一眼状态不必丢窗口
  • · 危险动作不再藏在右键里
  • · leverage：一套意图模型，两处视图共用
  • · 可测：意图与动作的映射是纯数据

3 · 展开是「改窗口高度」，窗口和内容没有共同的事实源

src/mini.tsx:79-82 ResizeMiniWindow · :317-328 maxHeight 过渡

Strong in-process

Before · 两套尺寸各算各的

React 算

52 + min(n*44+24, 320)

→ SetContentSize(w, h)

CSS 算

maxHeight: expanded ? 280 : 0

过渡 0.3s cubic-bezier

窗口瞬变（SetContentSize 无过渡），内容渐变（0.3s）。 两者错位 → 展开瞬间窗口已到位、内容还没长出来 = 白块；收起时内容还在、窗口已缩 = 裁切。

After · 一个尺寸源

内容定高

FitContent: true

窗口跟着内容走，不再由 JS 反算高度

上限交给 MaxHeight

mygo 的 FitContent 文档：「sizes the page area to its page's content, and follows it as it changes」 —— 正是这个场景。

Problem

展开高度由 React 用 n*44+24 估算后调 SetContentSize，CSS 另用 maxHeight:280 做过渡。两套常数、两种时序，必然错位。而且 320 / 280 两个魔数互不相干。

Solution

让内容定高：窗口用 FitContent 跟随内容，上限用 MaxHeight。React 不再调 ResizeMiniWindow。

Wins

  • · 展开/收起无白块、无裁切
  • · 删掉 ResizeMiniWindow 与两个魔数
  • · 内容增减自动跟随，不用重算
  • · locality：尺寸只有一个来源

4 · 一个位置都记不住，StateKey 根本没设

main.go:994-1005 WindowOptions 无 StateKey

Strong in-process

Before · 每次重启回到原点

屏幕

悬浮窗（居中）
用户拖到右下角
→ 重启 → 回到中间

主窗口有 StateKey: "main"， 悬浮窗没有。同一个应用，两个窗口两套标准。

After · 记住位置，且不出屏

StateKey: "mini"
Panel: true
CornerRadius: 24
// 位置/尺寸/展开态自动恢复

mygo 文档：StateKey 记住位置、尺寸， 且「as long as it would show on a connected display」—— 换显示器不会跑到屏外。

Problem

悬浮窗每次启动都在默认位置，用户拖到哪都不被记住。展开状态也不持久化。AlwaysOnTop + SkipTaskbar 已配，却漏了 StateKey。

Solution

加 StateKey: "mini"。同时 Panel: true 更贴合「启动器式浮层」的定位：跨 Space、压全屏应用、不抢焦点。

Wins

  • · 拖到哪就在哪，重启不丢
  • · Panel 修掉「跨桌面就看不见」
  • · 与主窗口同一套持久化约定

注意

Panel: true 在 macOS 上「不激活 app 就给键盘」，正是浮层想要的； 但它不能最小化/最大化全屏，要确认没和现有 ToggleMiniWindow 的 Show/Hide 逻辑冲突。

5 · 动画是状态缺失的补丁：时间要从事件里来

src/mini.tsx:23-35 startTimes · :100-107 formatElapsed · 无限 pulse

Worth exploring in-process

Before · 前端在猜后端的状态

startedAt

前端首次看到 running 时打时间戳

→ 悬浮窗晚开就少算，切窗口就重算

lastOutput

拼 agentDelta，只留末 100 字符

→ 无标点边界，截断处难看

errorMsg

前端硬编码 '执行出错'

→ 真实错误不显示

动画

pulse 1s infinite / errorPulse 0.8s infinite

→ 一直闪，长任务看着累

After · 后端给事实，前端只呈现

MiniAgentStatus {
  Status · StartedAt · ErrMsg
  LastOutput · QueueLen
}

时间戳由 agent 自己记，窗口晚开也准

错误原文透传，不硬编码

运行中呼吸 2–3s 缓动，非 1s 闪

Problem

计时、错误文案、输出片段全靠前端从增量事件里猜。MiniStatus 这个 interface 少了三个字段，于是每个消费者都要自己重建一遍，且重建结果不一致。

Solution

把 StartedAt / ErrMsg / LastOutput 加到 MiniAgentStatus，由 agent 层维护。前端删掉 startTimes / lastOutputs 两个 ref 和所有硬编码文案。

Wins

  • · 时间准确，与窗口开没开无关
  • · 真实错误可见，不再「执行出错」
  • · 删掉两个 ref + 三处硬编码
  • · leverage：一个 interface 服务主窗与悬浮窗

Top recommendation

先 #1（拖动吞点击），再 #3（尺寸错位）

#1 是根因，不是手感问题。你感觉「拖动和点击总有问题」，原因是这两件事被绑在同一块区域且互斥： --app-region: drag 覆盖整条状态栏，mygo 对非 button 元素 直接 preventDefault()，于是状态点的 onClick 被吃掉。 顺带发现主窗口根本没有拖动手柄（也是 Frameless，但没有一处 drag）。

#3 是你说的「动画体验不好」。窗口高度是瞬变的， 内容高度是渐变的，两者各有各的魔数（320 / 280）。错位就产生白块和裁切。 换成 mygo 的 FitContent，让内容定高，这两个魔数一起消失。

#2 #4 各半天可完成，建议与 #1 同批。#5 依赖 agent 层加字段。#6 等 #5 完再说。
