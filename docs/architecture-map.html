02

分层架构：入口三种，内核一套

现在的形态不是「桌面应用」一件事，而是「驾驶舱 / 内嵌网关」两个入口共用同一个内核。 入口只负责收发，判断永远落在内核与治理层。

入口层三种入口
桌面窗口 · MyGo IPC网关 · HTTP + SSE飞书 · 长连接

桌面是驾驶舱（多 agent 并行、审批、diff、检查器）；网关管「人不在电脑前」的场景，只接管 web，属性过滤 / 去重 / 绑定在它这一层；飞书仍旧走 Hub，不经过网关。

绑定层main.go + api_*.go
102 个 API 方法24 个 mygo.NewEvent装配全部子系统

绑定层已从 main.go 拆成 11 个文件（agent / approval / channel / feishu / gateway / knowledge / memory / model / plan / skill / workspace）。只做校验、错误转换、事件发射，不做业务判断。

内核层agent · runtime · loop
agent.ManagerSupervisor + delegateruntime（native / ACP）loop.Runner

会话、队列、父子、拆任务；执行体抽象成可替换的 Runtime，输出统一成一套事件。循环的职责仍是造出「每次迭代之间」的控制点。

治理层副作用必须先过这一层
approval.Centerauditshellguarddiffworktreeskill

写操作走审批（允许一次 / 本会话允许 / 拒绝）；命令执行前先过 shellguard；每次副作用落 audit.jsonl；工作树让多个 agent 不再互相踩。

能力层工具 · 模型 · 记忆 · 调度
tool（builtin / web）llm（8 provider）memoryschedulerknowledgechannelbrowserpty

每个会话开跑前才装配注册表（最多 20 个工具）；本地模型继续在进程外；记忆是 SQLite，知识库仍是 JSONL，两者刻意分开。

支撑层config · proc · workdir · privacy

最底一层只面对平台差异：进程组怎么杀、用哪个 shell、目录是不是不该给的宽范围。

几条值得看的边

  • agent → 10 个包：它是装配中枢（approval / audit / memory / runtime / skill / tool / worktree / loop / llm / workdir），也是唯一知道「这一轮该调谁」的地方。
  • approval → tool：审批实现的是 tool.Approver 接口，方向是「治理适配工具」，不是工具依赖审批。
  • llm → tool / proc：provider 只需要工具的 Spec 与进程组能力，不反向依赖注册表。
  • tool → diff / shellguard / browser / proc / workdir：副作用边界全部从工具层伸出去，循环本身不碰这些。
  • scheduler →（无 import）：它只持有注入进来的 Runner，执行时调 Manager.Prompt，因此调度包可以单独测试。

分层纪律（仍然成立）

  • 依赖方向恒为 装配根 → 入口 → 内核 → 治理 → 能力 → 支撑；底层包不 import UI 层，事件类型各自定义。
  • channel.DecideReplies 仍是「谁该回」的唯一判定；runtime.NormalizeKind 是「不认识的事件怎么降级」的唯一入口。
  • 跨 goroutine 的返回值必须是副本；审批跨 goroutine 但靠 ctx 取消，停止不会留下挂死的等待。
  • 新增事件必须同时有前端订阅，否则 TestEveryBackendEventIsSubscribed 失败。

链路总览

05

执行循环：控制点仍插在每次迭代之间

委托给外部 CLI 时，「停止生效、结果结构化、预算可控、可中途干预」拿不回来——因为委托模式里没有「迭代」这个位置。 loop.Runner 就是在进程内造出这个位置；现在多了一层「副作用必须过治理」。

01 / 最前面 任何阶段
停止信号

先看 runCtx.Err()。被打断就进 PhaseStopped、写原因、落检查点。停止一律取消 ctx，审批等待也随之退出，不会挂死。

02 / 预算 只增不减
看门狗取代硬上限

默认只剩 4 小时墙钟（MaxWallMS）。轮次与工具次数上限保留字段但默认 0 = 不设限——长任务不再被 24 轮截断。暂停时长不计入墙钟。

03 / Steer 每次问模型前
插入用户插话

把后到的本会话消息 append 进这一轮，而不是等整轮结束。群消息不进这条路径，留到这轮结束再入队。

04 / iter.start 每轮刷新
轮次开始与上下文占用

迭代 +1、进 PhaseThinking，同时下发 ctxUsed / ctxBudget / ctxLimit。三个值必须后端算，前端自算不含 system 与内部 tool 轮次。

05 / 模型调用之前 顺序有讲究
检查点先落盘

模型调用是最贵的一步，之后落盘意味着崩溃时钱白花。Sync 顺便把完整消息拷回会话，不必等整轮结束。

06 / Compact 最多重试 4 次
收窗口，再调模型

先裁到约 8000 token（system 原文另算）。服务端仍报装不下就把预算减半重来，下限 512，而不是直接失败。

07 / 没有工具调用 终止条件
任务结束

assistant 正文、推理与 toolCalls 一起进历史；无工具调用即 PhaseDone + FinalText。工具回合留在历史里给模型看，不逐条冒到界面。

08 / 工具 逐个串行
执行前先过三道

schema 校验 → 指纹去重（同参第 3 次拦下）→ 写操作审批 → shellguard → 超时 → 头尾各半截断 → audit。任何一道拒绝都回填成 tool 消息，让模型自己改。

09 / 审批 fail-closed
等人决定，而不是默认放行

ask 弹审批、auto 按会话权限放行、readonly 一律拒写。默认 30 分钟超时按拒绝处理；auto 也不放开工作目录这条硬边界。

10 / 插话 用户优先
中途插话 = 放弃本批工具

这一轮已排好的工具全部不执行，逐个回填「这步先不做」。把新说明 append 进历史后继续下一轮。

11 / 防打转 3 轮
连续无进展就终止

连续 3 轮既没有成功的工具调用、也没有最终答案，判定原地绕圈，PhaseFailed。再跑只是烧预算。

12 / 结局四种 返回值是状态
done · stopped · budget_exhausted · failed

治理层失败是正常结局，不是异常。真正的 error 只留给「跑不下去了」——模型调用本身不可用。

默认预算

4 小时
MaxWallMS · 看门狗
0 不限
默认轮次 / 工具次数
~8k token
单轮提示预算（system 另算）

检查点跟每次模型调用走，不按 token 落盘；同一会话的检查点在 loop/runs，能接上就续跑，已用预算不清零。

会话状态机

idle→ 入队 → queued→ worker 取到 → running→ 结束 → idle /error
running或queued → BlockAgent →blocked → Unblock →idle

一轮正常结束按队列是否为空回到 idle / queued，不停在 done，也不留绿色的「完成」点。审批等待期间会话是 blocked，文案用 blockedReason。

06

工具与模型：循环能伸出去的手，现在都带闸门

每个会话开跑前才装配注册表（tool.NewRegistry()），最多 20 个工具。文件工具钉在工作目录内；多根工作区可挂附加目录，但 bash 的 cwd 仍是主目录。

工具类别副作用行为与边界
read_file文件只读只碰工作目录（含附加根）内的文件。
glob文件只读按模式找文件，避免模型用 bash 拼 find。
grep文件只读正则搜索内容，返回命中行与位置。
write_file文件写需要审批；写前生成结构化 diff 供人判断。
edit_file文件写oldText 必须与原文完全一致且唯一，否则报错让模型自己改。
apply_patch文件写按补丁批量改动，比逐处 edit 少一轮往返。
bash命令执行默认 60 秒杀进程组；不读登录脚本；先过 shellguard，再落 audit。
web浏览器网络按控件编号或页面文字操作内置浏览器，一次最多 12 步，只交回最后一页。
list_agents会话读看有哪些会话、各自在做什么、是否空闲。
ask_agent会话协作按名字把任务交给已有会话并等回复；互相等待会被拦住。
create_agent会话协作新建子会话，沿用同模型与工作目录；名额 6 只算模型自建的。
delegate会话协作把一个任务切成几块并行做，再收成一条汇总；用于单轮内批量派活。
delete_agent会话写只能删自己，或自己创建的子会话。
invite_to_channel会话协作把某个会话拉进频道，让群聊里能找到它。
list_notes知识读看知识库里的笔记（事实类资料）。
save_note知识写写一条并挂到自己身上，下一轮进系统提示。
read_skill技能读按名字取技能全文。系统提示里只放名字与一句描述，正文按需加载。
save_skill技能写把「怎么做这类事」沉淀成可复用步骤。
memory_search记忆只读查 events + notes + facts，中文走 FTS5 trigram，空结果明确说「没有找到」。
set_profile自我写改自己的名字、简介或工作目录。

权限模式：三档，且刻意没有第四档

ask · 每个写操作都问你（默认最保守）
auto · 按会话权限放行，仍在工作目录边界内
readonly · 写操作一律拒绝，只读可用

auto 不等于完整权限：工作目录是工具层的硬边界，审批模式不放宽它。 无论哪一档，shellguard 对危险命令的拦截都照旧生效。

07

六个新子系统：这一版真正长出来的东西

每一个都在主进程里跑，都随应用启动 / 退出，不单独起进程（网关的常驻形态除外，本轮未启用）。

gateway · 1,522 行

内嵌网关

四条路由：/api/inbound（收消息）、/api/status、/api/agents、/api/approvals； 出站走 SSE。只接管 web：属性过滤、去重、会话绑定都在这一层，绑定记在 gateway-bindings.json。

它是个库，host 接口注入 Manager / approval.Center / FileBinder / SSE Sender。

runtime · 1,988 行

运行时协议

mad.runtime/1：把「谁在执行」抽象成可替换的 Runtime，输出统一成一套 Event。 native 走进程内 loop 适配器，ACP 走 JSON-RPC over stdio 的外部进程。

规则：只增不改；未知事件降级成 notice，不因为对端升级就断线。

memory · 1,090 行

跨会话记忆

单文件 SQLite（memory.db，纯 Go 无 cgo），FTS5 trigram 做中文召回。 自动写入只认 agent.message 的 user / assistant 文本，跳过 delta、工具、推理。

sha1 去重；每 agent 每分钟 60 条限流；超 8000 字符保留头尾。

scheduler · 1,211 行

计划调度

interval / cron-lite 两类任务，落 schedules.json，30 秒心跳。 默认 23:00–08:00 静默；每任务与全局令牌桶限频；失败按 30s × 2^n 退避，上限 30 分钟。

执行只调 Manager.Prompt 入队，不伪造回复；审批照旧，超时按拒绝。

approval · audit · diff · shellguard

副作用治理四件套

审批把「同步 if」变成可等待的队列：worker 挂起等，界面点允许 / 拒绝 / 本会话允许。默认 30 分钟超时按拒绝。 audit.jsonl 独立成册，会话删了也查得到；shellguard 两层判定（正则黑名单 + 目标路径展开）。

只拦「敏感目录本身」，rm -rf node_modules 这类正常工作区一律放行。

skill · worktree · supervisor

技能、工作树、拆任务

技能存「怎么做」（知识库存「是什么」），清单进提示、正文按需 read_skill。 工作树共用 .git，只换检出目录与 mad/<slug> 分支。 Supervisor 一句话拆最多 3 个子任务，20 分钟总时限，子会话默认各建工作树。

解绑与物理删除分离：删不掉也能先关掉，不留半个仓库。

启动顺序：谁先起来

数据目录→ memory.Open→ scheduler.New→ gateway host→ feishu.Hub→ 主窗口 / IPC

关闭时按相反顺序：先停调度心跳并等 goroutine 结束，再关记忆库，不留下半写入的文件。
