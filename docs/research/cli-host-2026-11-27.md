# CLI host: which terminal coding-agent UI can sit in front of `agent.Manager`

> 2026-11-27. Primary sources are each repo's license file, README, and the source file that constructs the interactive UI, read from a depth-1 clone at the commit named below. GitHub's REST API was rate-limited from this network, so license text was taken from the git blob, not from the license API.

## Conclusion

No open-source coding-agent TUI can be copied into this process as a product-quality screen in front of the existing Go runtime.

The closest UX reference is Pi (`badlogic/pi-mono`, MIT): transcript, editor, tool rows, and slash commands. It is TypeScript. It cannot be embedded, and its screen is constructed around Pi's own `AgentSession`, not a foreign runtime.

The recommended path is to keep `agent.Manager` and the existing `-headless` entry (`runHeadless` → `runTermUI`). Do not vendor Crush, Pi, OpenCode, Codex, Gemini CLI, goose, Aider, pi-go, or codeany. The screen to adapt is MothX (`oschina/mothx`, MIT, Bubble Tea v1): lift its transcript, editor, slash menu, approval, and tool modal onto `cli_tui.go`, and leave its agent loop and session store behind. Use Pi only as the interaction spec. MothX is not a drop-in `New` in front of `agent.Manager`; see section 9.

License risk of that path: Bubble Tea and Bubbles are MIT. No other project's code is copied, so FSL, BUSL, AGPL, and Apache notice duties do not attach. Copying Pi's TypeScript later would be allowed by MIT only after a rewrite into Go, and only if the agent loop, session store, and providers stay out.

## Constraints this note does not relax

- One Go process. The desktop window stays. The CLI is a mode of the same binary.
- The runtime stays `agent.Manager`. `RunPrompt` is `internal/agent/manager.go`. Approvals, tools, and sessions stay there. A candidate that only works by adopting its own session database or agent loop is a miss.
- The screen has to be a product: transcript, editor, tool rendering, slash commands. `cli_tui.go` (785 lines, `package main`, Bubble Tea `textarea` + `viewport`, eight slash commands) is the hand-rolled screen that was already rejected. It is evidence of the seam, not a candidate to extend in place as "the UI".
- The destination may be a proprietary or internal app. A license that allows only internal use, or that forbids a competing product, fails.

## How to read a verdict

"Separable" means the UI model is constructed against a small interface (draw this, user typed that) and does not import that project's session store, provider clients, or agent loop. Every complete coding agent below fails that test. Toolkits pass it and are not products.

SPDX: none of the `LICENSE` / `LICENSE.md` / `LICENSE.txt` files below contain an `SPDX-License-Identifier` line. Where the text is the MIT license or the Apache License 2.0, the SPDX ids are `MIT` and `Apache-2.0`. FSL names itself in the file and is not an OSI license.

## Recommended path

Keep this binary and this runtime. The CLI mode draws with Bubble Tea (MIT) and sends work to `agent.Manager` (`RunPrompt`, the existing approval and tool path, the existing sessions).

Do not vendor another agent's runtime. The one screen whose pieces can be copied is MothX, and only the view. In particular:

- Do not copy Crush's `internal/ui`. FSL-1.1-MIT Competing Use, and `ui.New` requires Crush's workspace and sqlite app.
- Do not copy Pi's `InteractiveMode`, OpenCode's `Tui.run`, Codex's `App`, or Gemini's `AppContainer`. Wrong language, and each one is constructed with that product's session.
- Do not copy pi-go's `tui.Run` or codeany's `NewModel`. MIT, Go, and each constructor takes that project's agent.
- Do not revive archived `opencode-ai/opencode` `tui.New(app *app.App)`.
- Do adapt MothX's `internal/tui` view (editor, slash suggest, approval, tool modal) onto `cli_tui.go`. Do not call `NewApp`, and do not take `provider`, `session.Manager`, or `agent.Agent`.

What to take from Pi, as behavior only: a scrollable transcript, a real editor (not a one-line input), tool calls rendered as their own rows, and a slash-command popup whose commands call this app's session and approval code. `packages/tui` shows which widgets a product needs (editor, markdown, scroll view, autocomplete). It is not code to paste.

`cli_tui.go` can remain the place the mode starts, because it already lives in `package main` and already talks to `agent.Manager`. The work is replacing that screen with the product surface above, not wiring a second agent loop beside it.
