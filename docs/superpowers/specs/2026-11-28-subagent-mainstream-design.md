# 子任务改成主流形态（临时子 agent，就地修改）

日期：2026-11-28
状态：已确认方向，实施中

## 为什么改

`delegate` 的写任务现在每块活都新建一个常驻子会话，再开一个独立 git 工作树和分支。结果是：

- 每次派活都多出几个会话，改动散在各自分支上，父会话拿到的只有每块最多 1200 字的摘要，还要再合并。
- 模型没写 `mode` 时按文本猜，猜不出来一律走这条重路径。
- 系统提示里没有一句讲什么时候该派，工具说明里大半是「不要用的情形」。本机会话数据里 `delegate` 一次都没被调用过。
- 只读子任务只有读文件、搜索、抓网页四个工具，却用着主会话的提示词，里面要求它调用自己没有的 `verify` 和 `repo_map`。
- 子任务改了什么，父会话的界面上看不到 diff。

Claude Code 的 Task、Cursor 的 subagent 都是另一种形态：临时的、独立上下文、在同一个目录里干、跑完把最后一条消息交回父对话。这次按这个形态改。

## 改成什么样

### 三种形态

| mode | 是什么 | 会话 | 工作树 | 工具 |
|---|---|---|---|---|
| `read` | 只读临时子任务 | 不建 | 不开 | 读文件、搜索、`repo_map`、抓网页 |
| `write` | 临时子任务，在父会话目录里直接改 | 不建 | 不开 | 读写文件、`apply_patch`、`bash`、`verify`、搜索、`repo_map`、抓网页 |
| `isolated` | 旧的 write：常驻子会话加独立工作树 | 建 | 开 | 完整主会话工具 |

- 省略 `mode` 时按任务文本推断，拿不准按 `write`。`write` 现在是轻路径，猜错的代价是多给了写能力，而写仍然要过审批。
- Supervisor 会话不带推断，照旧走 `isolated`，行为不变。
- 临时子任务没有派活工具，不能再往下派。

### 写任务的护栏

临时写任务不是绕过治理的后门，下面这些和主会话走同一套：

- **审批**：用父会话的审批身份。父会话是 ask 就弹卡片，是 readonly 就直接拒，记住的放行规则也一样生效。
- **过期写检查**：每个子任务有自己的读写版本作用域。两个子任务改到同一个文件时，后写的那个会收到 `STALE_WRITE`，必须重新读再改。父会话之后再改这个文件也一样。
- **写意图广播**和**审计**：照常发、照常记，署名是「父会话 › 子任务名」。
- **停止**：父会话停止，子任务跟着取消。

### 交回给父会话的内容

- 子任务的最后一条消息，上限从 1200 字放宽到 4000 字。
- 改动文件清单和每个文件的增删行数。这份清单由工具结果统计，不取自模型的自述。
- 子任务改了代码文件时，`delegate` 的结果带 `wroteCode` 标记。父会话的循环把它当成一次代码写入：收尾前没跑 `verify` 会被拦一次。几个子任务并行改完之后，由父会话验一次整体。

### 界面

- 子任务每次成功写文件，都以父会话的身份补发一条工具结束事件，带路径、diff 和子任务名。终端界面和桌面端都按普通工具结果渲染，于是子任务的 diff 出现在父对话里。
- 终端界面的子任务树里，写任务标「就地修改」。
- `-p` 和管道模式：写文件后往 stderr 打精简 diff；审批提示里带上说明和 diff。

### 提示词

- 主会话系统提示加一条派活规则。静态段因此变一次，之后仍然逐字节稳定。
- 临时子任务换成自己的提示词，只提它真有的工具。
- `delegate` 的工具说明重写：先讲什么时候用，再讲什么时候不用，再讲三种形态。

## 不做

- 子任务不继承 MCP 工具、插件工具、笔记和记忆工具。
- 不做「复用已有空闲子会话」。
- 不改桌面端前端代码。桌面端靠已有的「只收到结束事件也补一条记录」的逻辑显示子任务的改动，本次没有在桌面端实际跑过。
- 会话恢复后，子任务的逐条 diff 不会重现；`delegate` 结果里的改动清单还在。

## 验收

| 场景 | 期望 |
|---|---|
| `mode=write` 派一块改文件的活 | 父目录里的文件被改；会话名单不增加；不出现 `.mad-worktrees` |
| 同上 | 回传里有改动文件和增删行数；结果带 `wroteCode` |
| 同上 | 父会话收到带 diff 和子任务名的工具结束事件 |
| `mode=isolated` | 仍然建子会话和工作树 |
| Supervisor 派活 | 仍然走 `isolated` |
| 只读子任务的提示词 | 不提 `verify`；工具表里有 `repo_map` |
| 父循环收到 `wroteCode` 的 `delegate` 结果后直接收尾 | 被拦一次，要求先 `verify` |
| 终端界面收到子任务的写事件 | 对话流里出现 diff 和子任务名 |
| `-p` 模式写文件 | stderr 出现 `+`/`-` 行 |
