# 飞书多个自建机器人

日期：2026-11-20

设置里的飞书页从一份机器人配置改成一份名单。每个企业自建机器人有自己的 App ID、Secret、默认会话、用户授权和长连接。点一行，下面只编辑那一个。

界面沿用现在的设置卡片、厂商名单和状态胶囊。颜色和间距用现有 token，遵守 `docs/skills/ui-design.md`。

## 页面

页头：把企业自建机器人接到本机会话。每个机器人单独保存。

名单在上，编辑区在下。同时只打开一个编辑区。

没有机器人时，名单里写「还没有机器人」，旁边是「添加」。

每一行显示：

- 名字。空名字显示 App ID。App ID 也空时显示「未命名」。
- 连接状态：已连接、连接中、连接失败、未连接。
- 接到的本机会话名字。会话没了就显示「会话不存在」。
- 行尾的启用开关。

点一行打开它的编辑区。点另一行就换成另一份。「添加」在名单末尾加一行还没保存的机器人，并打开它。关掉设置时，还没保存的新行丢掉。

删除在这一行上。已保存的要确认，确认文案是「删掉这个机器人？它的长连接会停掉。」确认后停掉它的长连接并删掉这份配置。还没保存的新行直接丢掉。删掉的机器人留下的群和私聊记录仍可在侧边栏查看，不再收到新消息。

## 编辑区

只出现当前这一行的字段：名字、启用、群里自己接话、App ID、App Secret、默认会话。

「启用」和「群里自己接话」放在同一行。授权和保存在同一行：授权是次按钮，保存是主按钮。

App Secret 已经保存过时，输入框留空表示不改，占位文案仍是「已保存，留空则不修改」。可以显示或隐藏正在输入的值。

「用我的飞书身份授权」只属于当前机器人。这个机器人还没保存过 App ID 和 Secret 时，按钮不可用。已授权时按钮写「已授权，重新授权」。

「保存」只写入当前机器人。启用前要有 App ID、App Secret，以及一个存在的本机会话。缺了就沿用现在的三句错误：启用前要填写 App ID、App Secret，并选择一个会话；会话还没准备好；绑定的会话不存在。

开通权限、事件订阅、回调地址收进「连不上时」，默认合上。原文保留。连接失败时，失败原因直接写在编辑区，用现有的错误色。

行上的开关和编辑区的「启用」是同一个字段。已经保存过的机器人，拨动任一个都会立刻保存，并且只改启用；编辑区里还没点保存的名字、App ID、Secret、会话、接话方式不会被这次拨动写进去。还没第一次保存的机器人，开关只改草稿，要点「保存」才写入。启用失败时开关回到关闭，编辑区显示原因。名单每 2 秒刷新状态和失败原因。正在编辑时，不覆盖这一份还没保存的草稿。

## 数据

`config.json` 里的单个 `feishu` 改成 `feishuBots` 列表。每一项有 `id`、`name`、`enabled`、`appId`、`appSecret`、`agentId`、`mentionOnly`、`userAccess`、`userRefresh`、`userExpire`。Secret 和用户令牌仍留在这份 0600 文件里，不回给窗口。

读配置时，如果列表是空的、旧的 `feishu` 里却有开关、App ID、Secret、会话或用户令牌，就把那一份变成列表的第一项，写回文件，并去掉旧字段。`id` 在这次迁移时生成一次，之后不变。两边都有数据时以列表为准，下次保存去掉旧字段。

新机器人的 `id` 由服务端在第一次保存时分配。同一个 App ID 不能保存两次，第二次返回「这个 App ID 已经有一个机器人」。保存时如果 App ID 变了，清掉这个机器人的用户令牌。

接口：

- `ListFeishu` 返回全部机器人。每项含 `id`、`name`、`enabled`、`appId`、`hasSecret`、`hasUser`、`agentId`、`mentionOnly`、`status`、`detail`。不含 Secret 和令牌。
- `SaveFeishu` 保存一项。`id` 为空则新建。`appSecret` 为空则沿用已保存的值。
- `DeleteFeishu` 按 `id` 删除并停掉连接。
- `AuthorizeFeishuUser` 增加机器人 `id`，令牌只写回这一个。

每个开着的机器人各自一条长连接、各自的连接状态、各自正在进行的一次回答。保存或拨动开关只重启那一个。进来的消息用收到它的那个机器人的配置回复。

房间记下消息时带上机器人 `id`。没有单独改接过的群或私聊，用这个机器人的默认会话。`SetFeishuRoomAgent` 保持现状：按聊天 `id` 从下一条消息起改接，设置页这次不加这个操作。

## 测试

- 旧的单个 `feishu` 读进来变成一个机器人，再读一次不会变成两个。
- 保存第二个机器人不会停掉第一个的连接。关掉其中一个，只停那一个。
- 重复的 App ID 保存失败。启用时缺 App ID、Secret 或会话，返回现有的错误文案。
- Secret 留空保存后，原来的 Secret 还在。App ID 改了之后，该机器人的用户令牌被清掉。
- 没有单独改接的房间，回答用收到消息的那个机器人的默认会话。
