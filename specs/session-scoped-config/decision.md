# 会话级配置 + 知识库 + 群聊 — 决定

## 原话
"我理解这个工作目录应该是在这个会话中进行设置，不是在设置中进行设置的，包括现在的模型列表加载应该也是可以在现在的会话中进行配置调整。以及我觉得可以进行整理一个知识库？更好的方便多 agent 的进行实现？设置里面的悬浮窗口现在是没有必要的可以下掉。以及现在的群聊我好像没有看到怎么进行实现？感觉这块当时定义好的方案设计还是不够完善，导致现在需要频繁的调整和改动。"

## 根因
配置是**全局单例作用域**（`Manager.llmCfg` / `Manager.workDir` / `pty.Runner.dir`），
而产品语义是**会话作用域**。每个「按会话配置」的需求都被迫退化成「改全局 + UI 重复一遍」，
这就是频繁改动的来源。

## 我理解你要的是
1. **工作目录**从设置弹窗搬到会话内（AgentView 头部 chip）
2. **模型 + 模型列表加载**同样在会话内调整
3. **知识库**：人类写的约定，多 agent 共享，创建时自动带上
4. **设置里的悬浮窗口开关**下架（但迷你悬浮条本身保留）
5. **群聊（频道）**真正落地：能看到、能建、能发消息

## 可能理解错的地方
- "知识库" 可能是 RAG / 向量检索，也可能只是「人写的短笔记注入 prompt」。这里取后者（无外部依赖、零运维）。
- "群聊" 可能期望「多 agent 讨论并收敛出结论」。这里保持**广播触发**语义，不做编排。
- "下掉悬浮窗口" 可能指连带迷你窗一起删。这里只删设置里的**开关**，`Sidebar` 的「缩小到悬浮条」保留。

## 怎样算满足
- [x] 会话内可改工作目录，只影响该 agent
- [x] 会话内可改模型并加载模型列表，只影响该 agent
- [x] 设置弹窗不再有「窗口」「工作目录」
- [x] 知识库可增删查，全局笔记注入新 agent 的 system prompt
- [x] 可新建频道、选成员、发消息、看到消息落库
- [x] 会话级配置重启后不丢（`agents.json` 往返）

## 未知 / 取舍
- `LLMCfg.APIKey` 明文落盘到 `agents.json`：接受并 `// TODO(secrets)`，迁移到 `mygo.Secrets` 单独任务
- 频道消息只落 `channels.json`，不注入成员 agent 的对话历史（广播是「触发」不是「上下文」）
- 不引入 vitest（`config.yaml` 的 verify 只跑 `tsc --noEmit`），前端靠手测清单
