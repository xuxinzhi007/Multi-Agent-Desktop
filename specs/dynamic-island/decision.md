# 悬浮窗灵动岛改造 — 决定

## 原话
"悬浮窗灵动岛改造：运行中显示任务摘要，错误红色脉冲+角标，展开面板动画，hover tooltip显示当前任务"

## 我理解你要的是
把迷你悬浮窗从「静态状态条」升级成「灵动岛」式交互：
1. 运行中的 agent 在悬浮窗上显示**当前任务摘要**（如 "正在改 login.tsx"），不只是 "running"
2. 错误的 agent 在悬浮窗上显示**红色脉冲 + 数字角标**（多个错误时显示数量）
3. 点击展开的面板**有动画**（现在是无动画直接显示）
4. hover 状态点时显示 **tooltip**（当前任务详情）

## 可能理解错的地方
- "灵动岛" 可能指 iPhone 14 Pro 的 Dynamic Island 设计（黑色胶囊 + 状态图标 + 展开动画），也可能只是比喻「更灵动的悬浮窗」
- 任务摘要来源：从 agent 最近一条 user 消息提取？还是从 tool_use 事件提取？我假设从**最近一条 user 消息的前 30 字**提取

## 本质
悬浮窗是**状态概览 + 快速入口**，不是完整 UI。灵动岛设计的核心是：
- 信息密度：一屏看到所有 agent 状态 + 当前任务
- 视觉反馈：运行中/错误/排队 三种状态有明确视觉区分
- 交互流畅：展开/收起有动画，hover 有提示

## 怎样算满足
- [ ] 悬浮窗每个 agent 点 hover 显示 tooltip（当前任务摘要）
- [ ] 运行中的 agent 显示任务摘要文本（不只是颜色）
- [ ] 错误的 agent 红色脉冲 + 角标数字
- [ ] 展开面板有动画（slide/fade）
- [ ] 整体视觉接近灵动岛（黑色胶囊 + 圆角 + 状态图标）

## 未知
- 任务摘要具体提取规则（从 user 消息？从 tool 事件？）
- 灵动岛是否支持多 agent 同时显示（现在是一行一个）

## 这次不做

- 悬浮窗显示完整消息历史
- 系统通知集成
